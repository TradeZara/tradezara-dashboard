# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

A developer dashboard for the TradeZara organisation, served as a static page:
terminal theme (neon + scanlines), Chart.js 4.4 from a CDN. No build step, no
`package.json`, no installed dependencies — opening the file in a browser is the
only "run".

`index.html` is **build output**, regenerated by `generate.mjs` from
`template.html`. Never edit it by hand; the next run discards the change. Look
changes go in `template.html`, data changes in `generate.mjs`.

## Architecture

`generate.mjs` is a single plain-Node module (native `fetch`, no dependencies)
split into three stages — fetch, transform, render:

- **Fetch** discovers the org's non-archived repositories, then per repository
  pulls contributor statistics and closed pull requests.
- **Transform** (`buildModel`) is pure and is the only tested seam. It filters
  everything down to organisation members, aggregates by GitHub account, and
  derives every number the page shows from one intermediate structure — which is
  what keeps the headline metrics, the leaderboard and the charts from
  disagreeing with each other.
- **Render** substitutes `{{PLACEHOLDER}}` tokens in `template.html`. An unknown
  placeholder throws rather than leaking to the page.

A GitHub Action (`.github/workflows/refresh-dashboard.yml`) runs this every 5
minutes and commits only when the HTML actually changed. The spec specified an
hourly cron; the team shortened it afterwards.

## Constraints that are not negotiable

- The repo is **public** and measures **private** repos: the token lives only in
  CI, is read from an environment variable, and is never interpolated into the
  output. No browser-side fetching.
- Commit counts come from the *contributor statistics* endpoint, not the commit
  listing — that is what removes the artificial 300-commit ceiling. That endpoint
  answers `202` with an empty body while GitHub computes the stats: treat it as a
  retry, never as "repository with no contributors".
- Weekly series anchor on the weeks the API reported. Anchoring on the run clock
  misaligns the keys (the Unix epoch is a Thursday, API weeks start on Sunday)
  and silently zeroes every sparkline.
- Atomic failure: if collecting any repository fails after the retries, abort
  without writing the file.
- Only organisation members appear. This deliberately overrides the spec, which
  had decided to include bots.

## Tests

`node --test` with `node:test` + `assert/strict`, no framework and no mock
library — the convention inherited from the sibling `pip-matrix` repo. Fixtures
are written inline.

The only tested seam is the **pure transform** (raw API responses → dashboard
model). Network and HTML rendering stay out on purpose: tests must not know
internal function names or markup.

## Domain notes

`First` / `Last` dates are weekly buckets — the Sunday that opens the week, not
the day of the commit. A contributor with merged PRs but zero commits usually has
a commit email that isn't linked to their GitHub account.
